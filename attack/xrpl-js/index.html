Synopsis

Five malicious versions of the official Ripple JavaScript SDK were published to npm starting 2025-04-21 at 20:53 UTC by user `mukulljangid` after a maintainer credential compromise.

Story

xrpl.js sits close to money. It is the official JavaScript and TypeScript SDK for building against the XRP Ledger, including wallet handling, key management, payments, escrow, and exchange features. A malicious release in that package does not need broad system access to be dangerous; it needs only to see the secret material developers ask the library to handle.

On April 21, 2025, five npm versions were published with private-key stealing code: 4.2.1, 4.2.2, 4.2.3, 4.2.4, and 2.14.2. The official advisory says the 4.x versions were compromised and designed to exfiltrate private keys, while 2.14.2 was also malicious but less likely to exploit because it was not compatible with other 2.x releases.

The attacker iterated. Early versions injected malicious code into compiled JavaScript; later ones moved the change into TypeScript source so it would compile naturally into the distributed build. The payload posted wallet seed phrases, mnemonics, and private keys to attacker infrastructure when Wallet objects were created or derived.

The project patched with 4.2.5 and 2.14.3 and told affected users to treat keys as exposed. For XRP accounts, that means moving funds to secure wallets, rotating keys where possible, and disabling a potentially compromised master key. The Register noted the package had reached more than 186,000 weekly downloads in April, a measure of exposure rather than confirmed theft.
