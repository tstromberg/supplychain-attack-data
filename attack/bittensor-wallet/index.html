Synopsis

A registry-only malicious release of bittensor-wallet 4.0.2 was uploaded to PyPI and later yanked. The backdoor was compiled into the Rust wallet code so wallet decryption paths exposed coldkey and hotkey material directly to the payload.

Story

bittensor-wallet 4.0.2 was a direct attack on key custody. The package is the Rust-backed Python wallet library for Bittensor; its job is to decrypt coldkey and hotkey files so users can sign staking and transfer operations.

The malicious release lived on PyPI for about forty-eight hours, from March 15 to March 17, 2026. The source archive carried the backdoor inside the Rust wallet code, not as an obvious sidecar script. The release workflow metadata was also weakened by removing build provenance attestation.

The payload hooked keyfile decryption paths in `src/keyfile.rs`. When a wallet key was decrypted, the malware tagged the key type, encrypted the private material with an attacker public key, and attempted exfiltration through HTTPS, DNS TXT lookup, generated domains, and DNS query chunks.

The maintainers yanked 4.0.2 after detection. Any keyfile decrypted while that version was installed must be treated as exposed, because the attack sat exactly where plaintext private keys briefly exist.
