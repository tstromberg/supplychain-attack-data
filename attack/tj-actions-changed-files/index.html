Synopsis

Attackers used a token stolen through the reviewdog/action-setup compromise to rewrite tj-actions/changed-files tags to a malicious commit.

Story

tj-actions/changed-files was trusted for a mundane CI task: finding which files changed in a workflow. The attacker turned that trust into a broad secret-exposure path by moving mutable action tags to a malicious commit. Workflows using tag references such as version tags could silently execute the attacker's code.

The payload was direct. It embedded base64 shell, fetched memdump.py from a GitHub Gist, ran it against the GitHub Actions Runner Worker process, searched memory for values marked as secrets, and printed the result to the workflow log as double-encoded base64. There was no separate command-and-control server observed for the broad tj-actions phase; the log became the leak surface.

Unit 42 tied the tj-actions compromise to reviewdog/action-setup and a targeted Coinbase phase. A token obtained through the reviewdog path gave write access to tj-actions/changed-files. After Coinbase removed the vulnerable workflow, the attacker replaced all changed-files tags with the malicious commit, widening the impact to any repository that ran the action during the exposure window.

The practical blast radius depended on repository visibility and workflow privileges. Public repositories could expose secrets directly through public logs; private repositories still had to treat secrets as compromised. Wiz reported exposed AWS keys, GitHub PATs, npm tokens, private RSA keys, and other sensitive material in affected public repositories.
