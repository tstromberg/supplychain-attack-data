Synopsis

A compromised npm account published mailparser 0.1.2 in March 2019. The package used install-time execution to fetch and run attacker code from the registry path.

Story

The mailparser incident was a registry compromise, not a source repository change. Attackers obtained publishing access and released `mailparser@0.1.2` to npm.

The malicious release used the package installation path as execution. Anyone installing the affected version could run attacker code before application code had a chance to import the library.

Snyk and the npm advisory trail identify the release as malicious and tie it to a downloaded executable payload. The useful record is small: one package, one version, one registry artifact.

The package name is easy to confuse with later, legitimate mail parsing libraries. This record is scoped to the legacy `mailparser` npm package and its 2019 malicious `0.1.2` publication.
