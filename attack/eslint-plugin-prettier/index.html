Synopsis

The same npnjs.com npm maintainer phishing campaign that compromised eslint-config-prettier also compromised eslint-plugin-prettier.

Story

eslint-plugin-prettier was compromised in the same npm credential theft that hit eslint-config-prettier. The attacker controlled package publishing, not the source repository.

Versions 4.2.2 and 4.2.3 were published to npm as malicious releases. They rode a trusted package name used by projects that integrate Prettier formatting with ESLint, so dependency automation could pull them into workstations and CI jobs.

The payload family used install-time execution and a Windows DLL path. Socket reported that the injected code attempted to execute `node-gyp.dll` through `rundll32`, giving the attacker code execution at install time.

The response followed the eslint-config-prettier cleanup: token revocation, credential rotation, deprecation of malicious versions, and coordination with npm. This record remains package-specific because the affected versions and package coordinates differ.
