Synopsis

A pypj.org phishing page stole PyPI credentials and led to malicious num2words releases. Versions 0.5.15 and 0.5.16 appeared on PyPI without matching upstream GitHub releases.

Story

The num2words compromise followed a familiar Python package path: phishing first, registry publishing second. Attackers used the lookalike `pypj.org` domain to capture PyPI credentials and 2FA codes.

StepSecurity reported that the attacker created a new API token and published suspicious releases to PyPI. The first release, `0.5.15`, had no matching GitHub tag, commit, or release, which made the registry artifact diverge from the project source.

The package converts numbers to words, but its install base gave the attacker reach. The malicious releases were published through the official PyPI project, so ordinary package installation and dependency resolution were the delivery mechanism.

The record keeps both affected versions as artifacts and leaves broad download counts as exposure context. The durable lesson is simpler: package registry authority was enough, even when the source repository did not match.
