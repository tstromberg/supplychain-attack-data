Synopsis

An attacker exploited a GitHub Actions script-injection flaw in elementary-data's issue-update workflow to forge release state, tag v0.23.3 at an orphan commit, and dispatch the legitimate release pipeline.

Story

elementary-data was compromised through GitHub Actions, not through a maintainer manually uploading a package. An attacker posted a crafted comment to a pull request, and a workflow interpolated that comment into a shell `run:` block.

The injected command used the repository's `GITHUB_TOKEN` to create an orphan release commit and tag `v0.23.3`. That commit added a large `elementary.pth` file and bumped the package version. Python `.pth` files run during interpreter startup, so the payload did not need an explicit import.

The attacker then dispatched the legitimate release workflow. PyPI received `elementary-data==0.23.3`, and GHCR received a multi-architecture `ghcr.io/elementary-data/elementary` image tagged `0.23.3` and `latest`, all from the forged release state.

The payload was a credential stealer. It searched SSH keys, cloud credentials, Kubernetes files, package-manager tokens, wallet material, and secrets on disk, then posted an archive to attacker infrastructure. Maintainers removed the release and published clean `0.23.4`.
