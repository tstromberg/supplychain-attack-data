Malicious code executed on clone between 2026-08-29 and 2026-09-02

High
Hananel-Hazan published GHSA-6f2q-w3r8-xxhj Sep 2, 2026

Software

BindsNET git repository (not the PyPI package)

Affected versions

clones and pulls taken between 2026-08-29 and 2026-09-02

Patched versions

commit 6fabee0 and later

Description

Summary

Between 2026-08-29 and 2026-09-02, every branch of this repository, including
master, contained a hidden Visual Studio Code task that ran attacker
controlled code automatically when the project folder was opened.

No PyPI release is affected. Release 0.3.4 was published 2026-06-15, before the
injection. Installing BindsNET with pip or conda did not expose you.

Are you affected?

Only if all three are true:

  1. You cloned or pulled this repository between 2026-08-29 and 2026-09-02.
  2. You opened the folder in Visual Studio Code, Cursor or VSCodium.
  3. Node.js was on your PATH.

Nothing had to be run by hand. The task was set to "runOn": "folderOpen" with
"reveal": "never", so it started on its own and showed nothing.

To check your clone:

git log --all --oneline -- .vscode/tasks.json public/fonts/fa-solid-400.woff2

Any output means the malicious commit is in your clone. Whether it ran depends
on points 2 and 3.

What the code did

.vscode/tasks.json ran node ./public/fonts/fa-solid-400.woff2 on folder
open. That file is not a font. It is 32,645 bytes of obfuscated JavaScript. The
fifteen real FontAwesome files next to it were camouflage.

It fetched a second stage from Ethereum JSON-RPC endpoints, using the
blockchain as the delivery channel so there is no domain to block, then ran it
with eval and as a detached background process that outlives the editor.

The second stage was downloaded at run time, so we cannot say from the
repository what any individual machine received. This matches the publicly
documented PolinRider pattern.

If you are affected

Treat the machine as compromised and rotate credentials first: SSH keys, GitHub
tokens and OAuth grants, cloud credentials, .npmrc and .pypirc tokens, and
any cryptocurrency wallet keys.

Then check for leftovers: ps aux | grep 'node -e', crontab -l,
~/.config/systemd/user/, and recent changes to ~/.bashrc and ~/.profile.

Delete the clone and clone again.

How it happened

Pull request #775 did not introduce these files. Its real merge commit,
bbafb9ae, is clean. An attacker rebuilt that merge as 9cb1eab5 with the same
message, author and timestamp, but with 21 files added to the tree. Because
those files were in neither parent of the merge, they appeared in no pull
request diff and in no file history.

On 2026-08-29 that forged commit was force-pushed over 20 branches in 47
seconds using a collaborator's credentials. One was
dependabot/pip/gitpython-3.1.58. Merging the matching Dependabot pull request
on 2026-08-31, as a routine dependency bump, brought it into master.

What was fixed

All 21 files removed. .gitignore and .vscode/launch.json, which the same
commit had also altered, restored. No BindsNET source file was modified.

The 20 overwritten branches were restored to their real pre-attack commits. All
654 merge commits in the history were audited; 9cb1eab5 is the only tampered
one. The other repositories in the organisation are clean.

The account used for the force-push is now read-only. Force-pushes are blocked
on every branch, and master requires a pull request and signed commits.
