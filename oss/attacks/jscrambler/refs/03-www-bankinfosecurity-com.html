Jscrambler npm Breach Exposes Developers to Malware

Malware Harvested Cloud Credentials, Source Code and Deployment Tokens Tiffany Wang • July 13, 2026    
  • Share
    Post
    Share
  • Credit Eligible

Hackers poisoned a JavaScript application used in a code integrity security platform, the latest in a series of software supply-chain hacks against the npm and other software code repositories.

See Also: OnDemand | Transforming Third-Party Cyber Risk Management: From Compliance to Actionable, Automated, and Risk-Based Programs

Developers of the jscrambler platform said they first identified on Saturday the "unauthorized publication of a malicious version of our jscrambler npm package" that had been downloaded nearly 1,500 times.

The unauthorized update would prove the first of a series of malicious five packages published to the jscrambler npm repository over roughly three hours as defenders scrambled to take down malicious versions as they mushroomed back. Versions 8.14.0, 8.16.0, 8.17.0, 8.18.0 and 8.20.0 of the jscrambler code integrity API client are spiked with malware.

Hackers varied the infection method but never the payload, a Rust-built, cross-platform infostealer, found analysis by software security firm Socket.

Jscrambler determined hackers were able to push poisoned payloads to the npm repository by using valid credentials. "We have revoked and rotated all relevant credentials, passwords and secrets, and have implemented additional security controls around our publishing process while the investigation continues," the firm said.

"Depending on where the package was installed, the malicious binary may have executed with access to source code, environment variables, build credentials, deployment tokens and other secrets available to the npm process," Socket wrote.

The malware exfiltrates stolen data to an attacker-controlled server, Socket said. It also uses stolen credentials to access cloud services, Kubernetes environments and AWS Secrets Manager and Systems Manager.

The first three compromised versions ship two malicious files: Setup.js, a small loader that executes during installation even if the package is never imported. It detects the operating system and chooses the corresponding executable embedded in intro.js, a payload container disguised as a JavaScript file.

Starting with version 8.18.0, hackers adjusted tactics to inject the dropper as a self-executing function activated when the package was imported or its command line interface run, rather than at install time. "This is a deliberate evasion: it defeats scanners that only inspect preinstall/postinstall scripts and survives," Socket wrote.

The malware targets browser-extension cryptocurrency wallets, warned analysis by StepSecurity. It also looks for cloud credentials in Google Cloud, AWS and Azure, data in messaging platforms like Discord and Slack and session cookies in Chromium-family browsers and Firefox.

Code repositories have come under sustained attack, whether through social engineering attacks against developers, stolen credentials, typosquatting or wormable malware that scrapes tokens (see: Automated 'Megalodon' Campaign Spreads GitHub Repo Backdoors).

Developer workstations, with their access to repositories containing secrets, credentials and code, are primary hacking targets. "Attackers no longer need sophisticated zero-days. They exploit trust in everyday tools," said Boris Cipot, principal security engineer at Black Duck, after the May theft of internal GitHub repositories (see: GitHub Hacked, Internal Repositories Offered for Sale).

Risk Management Framework: Learn from NIST

90 minutes · Premium OnDemand 

Overview

  • Twitter
  • Facebook
  • LinkedIn

From heightened risks to increased regulations, senior leaders at all levels are pressured to improve their organizations' risk management capabilities. But no one is showing them how - until now.

Learn the fundamentals of developing a risk management program from the man who wrote the book on the topic: Ron Ross, computer scientist for the National Institute of Standards and Technology. In an exclusive presentation, Ross, lead author of NIST Special Publication 800-37 - the bible of risk assessment and management - will share his unique insights on how to:

  • Understand the current cyber threats to all public and private sector organizations;
  • Develop a multi-tiered risk management approach built upon governance, processes and information systems;
  • Implement NIST's risk management framework, from defining risks to selecting, implementing and monitoring information security controls.
